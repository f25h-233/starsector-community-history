# 贴吧帖目录数据集

**文件**：[`tb-index.csv`](tb-index.csv) · 18,177 行 · UTF-8 with BOM（Excel 双击可读）

百度贴吧"远行星号吧"**全量帖目录**（2012-07 – 2026-08）。它是把整个吧史从零散页面整理成的一份**可检索索引**——给了 `tid` 之后，任何人都能自己回去核对。

> ⚠️ **这是一份"标题索引"，不是内容存档。** 它只有标题、年份与回复数，没有帖子正文。

---

| 字段 | 含义 | 备注 |
|---|---|---|
| `tid` | 帖子编号 | 拼成 `tieba.baidu.com/p/{tid}` 即为原帖地址 |
| `year` | 创建年份 | 取自原始索引的创建时间 |
| `title` | 帖标题 | **已脱敏**，见下节 |

| `status` | 归档状态 | 空 = 正常；`数据删除 / 读取错误` = 本条被抹除，见下节 |

## 脱敏处理

规则与《[脱敏与编辑政策](../脱敏与编辑政策.md)》一致。本数据集做了三件事：

### 1. 群号与联系方式 —— 隐去，不设年代豁免
标题里出现的 QQ 群号一律替换为 `[群号已隐去]`，**共 4 条**：

| 年 | 处理后的标题 |
|---|---|
| 2013 | 招募游戏测试人员，修改武器数据舰船数据 `[群号已隐去]` |
| 2015 | 远行星Q群 吹水用 远行星号 `[群号已隐去]` |
| 2015 | 自制研究群 欢迎大家的加入 群号：`[群号已隐去]` |
| 2022 | 诸位`[群号已隐去]`萌新群答案不是0.95.1a么··· |

> 群号与联系方式**不受年代豁免**——它指向的是"可被骚扰的入口"，不是历史事实。

### 2. 未授权获取途径 —— 整条抹除，标记为读取错误
**共 18 条**（2012–2020）。这些标题被整条置为 `[数据删除]`，`status` 列标 `数据删除 / 读取错误`。原始标题**不在本仓库保留，也不在任何其它地方**；`tid` 与楼主名仍在——所以这条记录**存在**，只是**读不出来**。

**判定标准（严格）**：全表标题里提到 `破解 / 盗版 / 绿色版 / 3DM` 的共 38 条，逐条复核后只有三类算"获取途径"，才抹除：

| 类型 | 例 |
|---|---|
| **求 / 问哪里能拿到** | "谁有 0.52a 的单独破解补丁""有 521 英文破解版的吗""帮忙上传一份绿色版" |
| **宣告 / 发布其存在** | "远行星号 0.53.1a 有破解版啦""【填坑】…汉化破解版发布""3dm 有人放出了…" |
| **兜售 / 流通** | "0.91 有盗版了，还有人卖…出远行星号" |

**以下四类原样保留**——它们提到未授权内容，但不指向获取途径：
1. **报错求助**："破解版老崩溃""窗口的字都不显示""破解版存档能转正版吗"——确认了解锁版本当年存在过，但不告诉任何人去哪拿
2. **否定表达**："没破解""无破解，需要序列号"
3. **入正 / 转正讨论**："以前玩盗版现在想入正""盗版转正可以用汉化吗"
4. **"破解"作"怎么打"解**："进星系跳出求破解""如何破解敌方舰队"

> 另有 1 条**反诈警告**（3DM 假破解提示）也保留——那是社区自净的记录，不是获取线索。

**为什么用 tid 名单而不是正则**：中文"破解"歧义极多（既指绕过授权，也指"怎么打"），正则要么漏判、要么误杀。名单逐条冻结在 [`build_dataset.py`](build_dataset.py) 的 `DELETE_TIDS` 里，拿着 tid 就能回原帖复核。

> **为什么叫"读取错误"而不是"已过滤"**：本数据集在设定上由一枚失联的欧米伽级核心整理（见仓库 README）。对这类条目，归档系统给出的就是故障信号，而不是一份删改记录。**这是叙事选择，不影响实质**——名单、数量、被抹除的行，全部公开可查。

为什么整条抹除而非保留为历史：这些标题里的渠道名（3DM 等）本身**不构成需要留存的社区史实**，留着只会让本仓库变回"当年去哪找"的索引。有史料价值的那部分——哪个年代有人在讨论非授权内容——在《[一、社区时间线](../01-社区时间线.md)》里以中性叙述记录，而不靠原始标题。

**补充**：真正的"求破解"高峰集中在 **2012–2015 年**——那时游戏还在 alpha、国内没有正规购买渠道。2020 年后此类标题几乎消失，剩下的是激活码找回、MOD 求助与入正讨论（**均不构成获取途径，原样保留**）。

## 关于 `author` 列为什么保留

这一列是**楼主**的名字，也是本项目一度犹豫最久的决定。保留的理由：

1. **这些名字本来就公开挂在每篇帖子上**，不是本仓库披露的；
2. **本仓库正文（笔记各章）已经在引用楼主名并作为证据**——索引里遮起来、正文里点名，只会让整件事显得可疑；
3. **遮一半更糟**：实测 763 条（4.6%）的昵称长度 ≤3 字，首尾打码后几乎等于没打；对少见昵称，可见的后缀足够反查。**一个做不到匿名的匿名化，只会制造"已经脱敏"的错觉**；
4. 考古需要"这个帖是谁发的"这一信息——去掉它，2012–2019 那段最有价值的归属线索就没了。

**同时明确几条边界**：
- 本数据集**只是帖目录**，**不是玩家名录**：没有按人聚合的清单，没有发帖量排行，没有个人主页
- **不提供任何跨平台账号对照**（这里的昵称与 B站、论坛账号之间没有映射）
- 再强调一次：本仓库不发布 uid、B站 uid、QQ 号、群号、邮箱、手机号

如果你是被列在这里、且不希望自己的昵称出现：**开 Issue 说明即可，不需要理由，我们会删除。**

## 数据质量（务必先看）

⚠️ **`author` 列的完整性随年份急剧下降。**

| 年份 | 条数 | 缺作者 | 缺失率 |
|---|---|---|---|
| 2012 | 374 | 0 | 0.0% |
| 2013 | 567 | 2 | 0.4% |
| 2014 | 208 | 0 | 0.0% |
| 2015 | 2099 | 7 | 0.3% |
| 2016 | 1045 | 3 | 0.3% |
| 2017 | 837 | 3 | 0.4% |
| 2018 | 896 | 9 | 1.0% |
| 2019 | 1066 | 15 | 1.4% |
| 2020 | 1193 | 65 | 5.4% |
| 2021 | 973 | 103 | 10.6% |
| 2022 | 1635 | 85 | 5.2% |
| 2023 | 1215 | 108 | 8.9% |
| 2024 | 1687 | 262 | **15.5%** |
| 2025 | 3048 | 572 | **18.8%** |
| 2026 | 1334 | 339 | **25.4%** |
| **合计** | **18,177** | **1,573** | **8.7%** |

**原因**：贴吧的新版页面不再把楼主昵称渲染进抓取所用的那一层结构。因此：

- **2012–2019 的 `author` 基本完整**（缺失 ≤1.4%）——这也是它最有价值的一段
- **2024 年起不可依赖**——四分之一的条目是空的
- 请按年份采信，**不要把它当作全时段可靠字段**

其他已知偏差：
- `reply_num` 是抓取时的快照，不是实时值
- 删帖、隐藏帖、被系统吞掉的帖无法计入
- 2026 年仅覆盖 1–8 月（1,334 条）
- 极少数"精品/置顶"标记可能因页面改版而缺失

## 可复现性

原始索引（`tb_full_index.json`）**不随本仓库发布**。生成脚本 [`build_dataset.py`](build_dataset.py) 一并公开——它完整写出了我们用了哪些正则、按什么规则抹除、哪些算假阳性（例如中文里"破解"可指"怎么打"、游戏黑话"白嫖"指免费蹭、入正讨论不算获取途径）。

**放着脚本，是为了让"到底删了什么、凭什么删"这件事可以被审计**，而不是请你相信一段说明。你有原始索引的话，跑一遍即可复现出**逐字节相同**的 `tb-index.csv`。

## 用法

```bash
# 按年份找热点
python - <<'EOF'
import csv, collections
rows = list(csv.DictReader(open('tb-index.csv', encoding='utf-8-sig')))
hot = sorted(rows, key=lambda r: -int(r['reply_num'] or 0))[:20]
for r in hot:
    print(r['year'], r['reply_num'], r['title'][:50])
EOF
```

要看正文：拿 `tid` 拼 `https://tieba.baidu.com/p/{tid}`。
